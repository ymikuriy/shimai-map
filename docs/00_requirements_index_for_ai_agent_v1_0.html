1. 資料構成の判断

結論：AI開発エージェントには「00_入口資料 + 機能別v1.0仕様書」を渡す。すべてを1つの巨大資料に統合しない。
理由1：参照しやすい
検索、登録、レイアウト、認証などを機能別に確認できる。
理由2：矛盾を追いやすい
仕様変更時に影響範囲が見える。
理由3：AIに依頼しやすい
この00資料を入口にして、必要な個別仕様書を参照させられる。

AIエージェントに1ファイルしか渡せない環境では、この00資料の内容を最初に貼り、続けて各仕様書を添付する。zip添付が可能なら、v1.0パッケージをそのまま渡す。

3. プロダクト要求の要約

目的
家の中のモノを、家族の誰でも検索して所在確認できるようにする。
主導線
検索/アイテム一覧 → アイテム選択 → 位置表示。
メイン画面
検索/アイテム一覧。下部タブなし。
管理導線
右上の設定アイコン → 管理/設定。
追加導線
右上の＋ → アイテム追加。

5. AI開発エージェントへの依頼文

以下をAI開発エージェントへ渡す依頼文として利用する。

あなたはスマホ向けWebアプリ開発エージェントです。添付のv1.0仕様書一式を唯一の採用仕様として読み込み、実装計画、技術選定、データモデル、画面実装順序、API設計、リスク、見積もり、MVPスコープを提案してください。draft版や旧版が存在しても参照しないでください。 重要条件： - このアプリの主目的は、家の中のモノを検索して所在確認すること。 - 下部タブは作らず、メイン画面は検索/アイテム一覧。 - 管理系は右上の設定アイコンから入る。 - MVPは1ユーザー=1家。家族共有はPhase2。 - 削除ルール、初回操作ガイド、レイアウト初期配置は08/07の仕様に従う。 - AI機能は05/08を読み、MVP実装可否・コスト・レスポンス速度・個人情報送信範囲・代替案を評価して提案すること。 - 仕様にない判断を勝手に確定せず、不明点は「要確認」として列挙すること。
