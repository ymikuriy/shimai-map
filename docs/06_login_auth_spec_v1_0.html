ログイン・認証仕様書

検索アプリのデータをユーザー単位で保護し、将来の家族共有・複数端末同期に拡張しやすいログイン/認証機能を定義する。

MVP：メール/パスワード 認証基盤利用前提 アカウント削除対応 将来：SNS/家族共有

1. 概要

本仕様書では、ログイン、新規登録、パスワード再設定、ログアウト、アカウント設定、アカウント削除を定義する。

結論：独自認証を作り込まず、Firebase Authentication / Supabase Auth / Auth0 / Cognito 等の認証基盤を利用する前提で仕様化する。アプリ側は画面・状態遷移・権限・データ所有ルールに集中する。
目的
家の中のモノ情報を、ユーザーアカウント単位で安全に扱う。
日常動作
ログイン済みなら自動で検索/アイテム一覧へ進む。
将来拡張
家族共有、複数端末同期、SNSログイン、MFAに拡張可能にする。

2. 基本方針

項目方針理由
ログイン有無ログイン必須部屋・収納・アイテムなどの個人/家庭データを保護するため。
認証方式MVPはメールアドレス + パスワード最も汎用的で、外部IDプロバイダに依存しない。
SNSログインPhase 2利便性は高いが、ストア審査・ブランドルール・実装分岐が増えるため。
MFAPhase 2 / 任意家庭内データの保護強化として有効だが、MVPでは登録負荷を抑える。
認証状態起動時に判定し、ログイン済みならS01へ毎回ログインさせず、日常利用をスムーズにする。
設定画面M01 管理/設定からアカウント設定へログアウト、退会、メール確認などを管理系に集約する。

7. アカウントモデル

設計方針：将来の家族共有に備え、認証ユーザーとデータの入れ物を分ける。MVPでは1ユーザーに初期ホームを1つ作る。
データ概要MVP将来拡張
UserAuth認証基盤が管理するユーザーID必須SNS/MFA追加
UserProfileアプリ側プロフィールメール、表示名、作成日時アイコン、通知設定
HomeSpace部屋/収納/アイテムの所属先登録時に自動作成家族共有、複数住まい
HomeMemberユーザーとHomeSpaceの関係ownerのみowner/editor/viewer

部屋、収納、エリア、アイテム、カテゴリ、人物ラベルは、原則として home_id に紐づける。

8. セキュリティ要件

分類要件仕様
パスワード長さ重視MVPでは15文字以上を推奨。実装制約がある場合でも最低8文字以上。英大文字/数字/記号の強制ルールは設けない。
パスワード入力入力補助パスワード表示切替、ペースト、パスワードマネージャ利用を妨げない。
漏洩対策弱いパスワード対策可能なら認証基盤の漏洩パスワード検知/ブロックリスト機能を利用する。
ログイン失敗レート制限連続失敗時は認証基盤の制限を利用し、アプリ側では汎用エラーを表示する。
エラー表示アカウント列挙防止「メールまたはパスワードが正しくありません」のような汎用文言にする。
セッション安全な保存トークンはOSの安全領域/認証SDKに任せる。平文保存しない。
ログアウトセッション破棄ログアウト時はローカルセッションを破棄し、A01へ遷移する。
重要操作再認証アカウント削除、メール変更、パスワード変更は再認証を要求する。
通信HTTPS必須認証情報やトークンは保護された通信経路でのみ扱う。
パスワードハッシュやソルト管理は、独自実装ではなく認証基盤に任せる。自前認証を選ぶ場合は、NIST/OWASPに沿った別途詳細設計が必要。

9. アカウント削除

アプリ内でアカウントを作成できる場合、アプリ内からアカウント削除を開始できるようにする。

項目仕様
入口A05 アカウント設定 → アカウント削除
確認「削除」などの確認入力 + 再認証
削除対象UserProfile、HomeMember、HomeSpaceに紐づく部屋/収納/エリア/アイテム/カテゴリ/人物ラベル
保持対象法令・不正対策・課金処理等で保持が必要なログがある場合は、別途プライバシーポリシーに明記
完了後セッション破棄 → A01ログイン画面へ遷移
Web導線Google Play配信時は、アプリ外から削除申請できるWebリンクも用意する

10. 実装方針

推奨

  • Firebase Authentication / Supabase Auth / Auth0 / Amazon Cognito等を利用
  • メール/パスワードをMVPにする
  • SDK標準のトークン管理を使う
  • アプリ側DBは auth_user_id と home_id で紐づける

非推奨

  • 独自でパスワードDBを作る
  • パスワードをアプリ内に保存する
  • 認証エラーで「メールが存在しません」と明示する
  • 周期的なパスワード変更を強制する

11. 仕様ID

ID仕様
AU-001アプリ起動時に認証状態を確認し、ログイン済みならS01、未ログインならA01へ遷移する。
AU-002MVPの認証方式はメールアドレス + パスワードとする。
AU-003新規登録時、UserProfileと初期HomeSpaceを作成する。
AU-004ログイン失敗時はアカウント存在有無を推測できない汎用エラーを表示する。
AU-005パスワード再設定はメール送信方式とし、送信後もアカウント存在有無を明示しない。
AU-006ログアウト時はローカルセッションを破棄し、A01へ遷移する。
AU-007アカウント削除はA05から開始し、A06で確認入力と再認証を行う。
AU-008アカウント削除後は関連するユーザーデータを削除し、セッションを破棄する。
AU-009パスワードの文字種強制ルールは設けず、長さと推測困難性を重視する。
AU-010M01 管理/設定にアカウント設定への導線を追加する。
